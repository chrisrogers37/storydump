## Summary

The second adapter on the media-source port. An admin pastes an album's public link in Settings; the route parses the token, probes the feed, creates the source, arms it for sync, admits it to the mix at the share left in the dialog, and the existing sync brings the album's photos in through the registry of phase 04, over the hosts phase 05 admitted. One migration widens two provider CHECKs. No credential row: the album is public by link. Built only after F10 keeps the album and the probe of phase 05 has confirmed the feed's shape and produced the fixtures. Cycle 1 changed four things here: the unused `ck_quarantine_provider` widening is gone; no stub adapter lives in `src/`; the album token is stored encrypted, because it works as a bearer credential; and the route answers its refusals by name and a repeated connect idempotently.

## Implementation Plan

### Dependencies

F10 locked as (a). Phases 01, 03 (its guide, and its migration ahead of this one), 04, 05; the probe's fixtures; F7 and F9 ratified.

### Blocks

None (the album is the last phase).

### Steps

1. **Migration `scripts/migrations/NNN_icloud_album_provider.sql`**, NNN the next free number at build time (F9): `ALTER TABLE media_sources DROP CONSTRAINT ck_sources_provider; ALTER TABLE media_sources ADD CONSTRAINT ck_sources_provider CHECK (provider IN ('gdrive','icloud_album'));` and a `-- runner:postcondition` reading `pg_get_constraintdef` for the new value. `provider_quarantine` is not widened: nothing in `src/` reads or writes it. Mirror: the next free `### §` in `07-security-model.md` with the identical fenced block (after phase 03's), its sha256 classified normative in `scripts/advertised_ddl_manifest.json`, the normative-block count pinned at `tests/scripts/test_advertised_ddl.py:292` raised by one, the file added to the ratified list in `tests/scripts/test_lineage_lane.py`, the CHECK widened in `accounts_sources_media.py:162`, and `scripts/migrations/adoption_manifest.json` extended as the previous migration's entry was.
2. **`src/services/target/icloud_album_adapter.py`** (new), implementing phase 04's `MediaAdapter` protocol. `album_ref_from(value)` accepts `https://www.icloud.com/sharedalbum/#<token>` or a bare token, refuses `album_link_invalid`. `validate_source_config(config)` requires the encrypted token (the same module-level contract as Drive's). `class ICloudAlbumAdapter(client, *, policy)`: `list_changes(config, checkpoint, *, source_id, workspace_id) -> (items, checkpoint)`; `fetch_bytes(config, file_ref, *, source_id, workspace_id, max_bytes) -> (bytes, name, mime)`, decrypting the token from `config` for the call and never returning or logging it; `checkpoint_incomplete(checkpoint)` true while `after` is set; and `probe(config) -> AlbumProbe`, called only by the connect route. Internals: `_base_url` (`p01` then the 330 redirect's host, cached in `config["host"]`), `_webstream(base, ctag)`, `_asset_urls(base, guids)` in chunks of 25 as the client does. Items: ref = the photo id; kind from the asset type; hash = the largest derivative's checksum; size; name `<id>.jpg` or `.mp4`; `category` = the album's name; `folder_path` None. Checkpoint `{v: 1, ctag, after}` (F7): ids sorted, `after` the last id handed out; a changed ctag restarts. An item absent from the listing is reported removed. Persistent failures raise `media_sync.DriveSourceGone` (the port's persistent class; its name is not renamed here). No stub lives in `src/`: the tests build the real adapter over an `httpx.MockTransport` scripted from the probe's fixtures, as `test_google_drive_adapter.py:1-11` does — #1325 deleted the Drive stub because a gate driven by a twin proves only the twin.
3. **Registration.** `vocabulary.py` gains `PROVIDER_ICLOUD_ALBUM` beside `PROVIDER_GDRIVE` (`:153`); `src/worker.py:864-877`: `adapters[PROVIDER_ICLOUD_ALBUM] = ICloudAlbumAdapter(client=..., policy=EgressPolicy(allowed_host_patterns=DEFAULT_ALLOWED_HOST_PATTERNS))`; the API's per-request builder beside `_drive_adapter` for the connect probe.
4. **Provisioning.** `get_or_create_album_source(executor, *, workspace_id, album_token, album_name, host)` writes `config = {v: 1, album_token_enc, album_token_sha256, album_name, host}`: the token encrypted through the credential ring (`ig_login_oauth.ring`, as `store_credential` encrypts a grant, `google_drive_oauth.py:383`), because it works as a bearer credential and `media_sources.config` is readable by `svc_clock` (`057_grant_matrix_and_archive_schema.sql:90-92`); idempotent on `(workspace_id, provider, config->>'album_token_sha256')` under the workspace's sources lock; a paused (removed) album connected again revives, as a folder does.
5. **The route.** `create_source` validates `provider` first — unknown is `provider_unknown` 400 before any work — and runs the album branch before the Drive-grant check (`v1.py:629-631`), so an album-only workspace never hears `drive_not_connected`. For `icloud_album`: `ratio` validated first, `0 < ratio < 1`, under its own reason; `album_ref_from`; `probe` through the album adapter, outside `principal.admin_session` exactly as the Drive read at `v1.py:656-662` is — the API's tenant sessions are armed with the egress in-transaction tripwire (`egress.py:347-352`), so a probe inside one raises. Refusals are `ProvisioningRefused` reasons mapped in `_PROVISIONING_STATUS` (`src/api/app.py:222`), so the web sees the reason and not only a status: `album_link_invalid` 400, `album_not_public` 409, `album_unavailable` 503 (timeouts, 5xx, `EgressRefused`), `album_refused` 502 (an unrecognised shape). A connect of an album already connected answers 200 `{source_id, created: false}`, idempotent as the folder pick is (`sources/route.ts:22-26`). Then create; `rearm_after_connect(session, workspace_id=…, source_id=…)`; the admit to the mix (F12) with the ratio and the admin as its author; 201. The Drive path is untouched. `remove_source` and `sync_now` work unchanged. `list_sources` adds `config->>'album_name' AS album_name` and never a token field; `_LABEL` becomes `COALESCE(folder_name, album_name, folder_ref, 'source')`. The docstring that says the route is closed to `gdrive` (`v1.py:615`) is rewritten.
6. **The web.** `SourceRow` gains `album_name`; the BFF POST forwards `provider`, `album_ref`, `ratio`. A new `album-card.tsx` beside `drive-card.tsx`, rendered by `integrations-tab.tsx` after the Drive card and mirroring the Folders block (`drive-card.tsx:227-307`): the list (`provider === "icloud_album" && state !== "paused"`), each row showing its source id, copyable, for `storydump sync`; "Add album" opening a dialog with the link field; the statement that anyone holding the link can see the album and that Apple's page names its owner and every contributor; a "Share of posts" field in percent, bounded 1–80, with a preview of how the other weights change; `aria-label`s as the Drive card has them; nouns chosen per provider rather than "folder"; Sync Now that does not depend on the Drive grant (`drive-card.tsx:287`); empty, pending and success states; refusal copy for each reason. The Sync Now and Remove handlers `drive-card.tsx` holds (`syncSource` `:151`, `removeFolder` `:94`) are lifted to a shared module. The weights card's folder wording becomes "source" (`category-weights-card.tsx:123-129`, `:141-144`). `firstSource` (`:428`) keeps its Drive meaning.
7. **Docs.** `documentation/guides/media-sources.md` (created by phase 03) gains the albums section: who can see a public album and what Apple's page shows, the admit share (F12), photos at 2048 px and video at 720p, Sync Now and Remove. `AGENTS.md`'s tech-stack line names iCloud Shared Albums. D37's contract table gains the `icloud_album` row. The docs guard battery green.
8. **CHANGELOG** under Unreleased.
