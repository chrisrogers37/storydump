### Fixed

- **A Drive daily limit no longer reads as a dead grant, and a folder the app lost no longer sends people to a reconnect (#1554).** The Drive adapter decided a 403 by its message alone. `dailyLimitExceeded` ("Daily Limit Exceeded") matched none of the quota words, so it read as `DriveCredentialDead`: a pointless token re-mint, then the sync flipped the source to `error` and alerted, for a limit that passes on its own. `appNotAuthorizedToFile` and `insufficientFilePermissions` (one folder or file the app may not reach) read the same way. Google's `errors[].reason` now decides first. The limits are retryable. The item refusals are `DriveSourceGone`, which the sync, the walk and the media fetch already read as the item gone to the app. Any other 401/403 stays the credential's, and only that re-mints the token. The message is read only when the body names no reason, so `storageQuotaExceeded`, a full Drive whose message mentions a quota, is no longer retried as a limit.
