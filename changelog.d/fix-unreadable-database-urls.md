### Security

- **The API refuses an unreadable `TARGET_DATABASE_URL` without quoting it.** It prints `TARGET_DATABASE_URL cannot be read as a database URL: write it as postgresql://user:password@host:port/database, percent-encoding every @ but the one before the host and any / ? # or % in the user or password, and check its port and each query parameter (or key/value option): its name, its = and its value.`, nothing chained; unset, its data routes answer 503.
- **The worker refuses the same URLs with the same sentence, and exits 2.** It used to boot on a host or name read out of the password. Both it and the API now read a raw `?`, `#`, `[` or `]` or a compatibility character in a password correctly, where they used to misread it, refuse it or crash.
- **The migration runner, the schema builder and the database scripts refuse a URL they cannot read, by its variable's name.** The scripts check libpq's own parse before connecting: a string it cannot parse or decode, or a database name or URL host it reads with an `@`, which a raw `/` in the password leaves. The builder refuses what SQLAlchemy cannot parse. A readable URL keeps the driver's own error.
- **Every process that takes a database URL refuses one with a second raw `@`.** Percent-encode every `@` but the one before the host as `%40`, and for `DATABASE_URL`, any `/` in the password as `%2F`. Now refused too: a raw `@` in a user name (`user@server`), a database name with an `@`, a raw `@` in a query value beside a user (a socket directory, say), and, for the runner and scripts, an abstract socket in URL form.
