### Changed

- **Gated command writes and the OAuth callbacks set the tenant once, not twice (#1624).** `commands.ingest` forwards `tenant_bound` to `execute`, and the web command adapter passes it as `command.workspace_id == tenant`, computed from the two values: its unit of work binds the tenant, so the gate skips the repeated `set_config` exactly when the command's workspace is that tenant. Both OAuth callbacks pass it too, since each opens its unit of work on the workspace it gates. That is one database round trip fewer per gated write and per connect callback. The membership read still binds both the workspace and the user, and the decision is unchanged: the gate's allowed and refused cases already run with and without `tenant_bound`.
