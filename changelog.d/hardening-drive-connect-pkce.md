### Security

- **The Google Drive connect flow uses PKCE (RFC 7636, S256).** Each Drive connect state is minted with a code verifier, stored on its `oauth_states` row encrypted under the credential key ring (`07` §51); the browser sees only the verifier's S256 challenge, in the authorization URL, and the callback sends the verifier with the code. A state without a verifier the ring can read is refused as `state_refused` before the code is exchanged, so a connect started before the deploy fails once and is started again. Google sign-in is unchanged: it keeps its OIDC nonce and sends no verifier.
