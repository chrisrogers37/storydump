### Fixed

- **Behind Railway, sign-in's limit was keyed on a Railway hop rather than the visitor.** After the edge was trusted, a live check showed the API keying on 152.233.47.69 while Railway's own Network Logs saw the visitor's address: the edge sends `X-Forwarded-For: <visitor>, <hop>`, and the right-to-left walk stopped at the hop, so every visitor through it shared one pre-auth counter. A new `DropEdgeHopMiddleware` in `src/api/app.py` removes that last entry when it is in `EDGE_HOP_HOSTS` (default `152.233.47.0/24`) and something precedes it, and the walk then reads the visitor. It removes exactly one entry and never the only one; a hop outside the list is kept and keyed on (shared, never chosen); an address in the list is never a trusted peer; and `EDGE_HOP_HOSTS` refuses `*` or a prefix broader than an IPv4 /16 or IPv6 /48. What it cannot tell apart is the hop from a client that itself holds an address in that range on a path where no hop is appended: that client's own entry is removed, which is safe only while Railway's edge writes the header itself rather than keeping a caller's value, so the list stays as narrow as the hops measured.
