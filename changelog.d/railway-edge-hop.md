### Fixed

- **Behind Railway, sign-in's limit was keyed on a Railway hop rather than the visitor.** After the edge was trusted, a live check showed the API keying on 152.233.47.69 while Railway's own Network Logs saw the visitor's address: the edge sends `X-Forwarded-For: <visitor>, <hop>`, and the right-to-left walk stopped at the hop, so every visitor through it shared one pre-auth counter. A new `DropEdgeHopMiddleware` in `src/api/app.py` removes that last entry when it is in `EDGE_HOP_HOSTS` (default `152.233.47.0/24`) and something precedes it, and the walk then reads the visitor. It removes exactly one entry and never the only one, so a client holding an address in that range on a path without the hop is still attributed to itself, never to an entry it wrote; a hop outside the list is kept and keyed on; and an address in the list is never a trusted peer.
