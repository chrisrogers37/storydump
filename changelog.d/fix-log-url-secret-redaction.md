### Security

- **The API's access log no longer prints query strings or the invitation token.** uvicorn's access line printed every request's raw query string, so each OAuth callback's `code` and `state` and each Meta data-deletion status `code` reached the API's logs, and it printed the live invitation token in `POST /api/v1/invitations/{token}/accept`. A filter on `uvicorn.access` (`src/utils/logger.py`) now prints `?<redacted>` for any query string and `<redacted>` for the token, and keeps the client address, method, path and status; the same filter covers uvicorn's trace-level request log. The API's own refusal lines and the cross-site refusal's message name a request by its route template, with only its workspace, command and row ids filled in. A provider callback that returns an error, or arrives without its state or code, says so in a line of its own, naming the error only when it is one of OAuth's seven standard codes.
- **httpx and httpcore log at WARNING in both services, held by tests.** httpx logs each request's full URL at INFO, and a provider URL carries the bot token, a client secret or an access token. The level was an untested import side effect that covered httpx alone; httpcore is pinned too, and a test fails if either service's import stops pinning them.
