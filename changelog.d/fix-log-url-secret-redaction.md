### Security

- **The API's access log no longer prints query strings, or anything after the invitation token's path prefix.** uvicorn's access line printed every request's raw query string, so each OAuth callback's `code` and `state` and each Meta data-deletion status `code` reached the API's logs, and it printed the live invitation token in `POST /api/v1/invitations/{token}/accept`. A filter on `uvicorn.access` (`src/utils/logger.py`) now prints `?<redacted>` for any query string, and wherever the path carries `/api/v1/invitations/` or a misdirected `/join/` (including under a root path, after a doubled slash, in an absolute-form target and in any letter case) it prints everything after that prefix as one `<redacted>`, so a token reaches the line only in a path that carries neither prefix before it. The client address, method and status print as before, and so does the path, through the prefix where it carries one. The same filter covers uvicorn's trace-level request log, which prints the masked path, and its raw path and query string as `<redacted>`. The API's own refusal lines and the cross-site refusal's message name a request by its route template, with only its workspace, command and row ids filled in, or before routing by its masked path. A provider callback that returns an error, or arrives without its state or code, says so in a line of its own, naming the error only when it is one of OAuth's seven standard codes.
- **httpx and httpcore log at WARNING in both services, held by tests.** httpx logs each request's full URL at INFO, and a provider URL carries the bot token, a client secret or an access token. The level was an untested import side effect that covered httpx alone; httpcore is pinned too, and a test fails if either service's import stops pinning them.
