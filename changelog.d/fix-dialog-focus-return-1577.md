### Fixed

- **Closing the Drive folder picker or the delete-workspace confirmation dropped keyboard focus to the top of the page (#1577).** Both Settings dialogs opened from component state, and Radix returns focus only to a dialog's own trigger. So after Escape, the ×, Cancel or the dialog's own action, a keyboard or screen-reader user started again from the top (WCAG 2.4.3, Focus Order). Add folder and Delete this workspace... are now their dialogs' triggers, as every other dashboard dialog's button already was. Deleting or restoring a workspace replaces the card's one button with the other, so the card moves focus to the button that takes its place, and Restore workspace is described by the sentence above it. `dialog-focus-contract.test.ts` fails when a dialog or sheet in the tree opens from state and says nothing about where focus goes.
