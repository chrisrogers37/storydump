### Tests

- **Tests pin the transport's dead-credential rule from both sides, and its one log line (#1553, a follow-up to #1493).** Only Telegram's own 401 is a dead token. A 404 that carries Telegram's error body, and a 401 that carries none (a proxy's page), each stay `ambiguous`: two new rows in `test_outbox_failure_record.py`'s reply table. Either misreading would have failed rows for good with no test going red. `test_a_dead_token_is_logged_once_while_every_send_is_counted` pins the latch: one ERROR line for three rejected sends, and `auth_failures` at three. The binding test (now `test_a_dead_tokens_failed_row_keeps_the_binding`) also requires the row to fail, so it goes red if #1493's change is reverted. `tests/mutations/outbox_failure_record.sh` gains six named mutations, one per pin. Two comments that still described a dead token as ambiguous (`vocabulary.OUTBOX_FAILURE_CLASSES` and `_send_media_card`'s docstring) are corrected, and so are two module docstrings that called a 403 a dead credential.
