### Added

- **A person can see and change what they planned, in the Queue and on the calendar (#1413, phase 6b).** A story planned from the Media library reads "Planned by <name>" in the Queue, and a Planned view (`/dashboard/queue?origin=planned`) shows those stories alone. The API applies that filter, so the view stays exact past the page limit. While a planned story waits in `scheduled` it can be rescheduled or cancelled. Reschedule… opens on the story's current time, read and named in the story's own zone, and moves the same story; it is keyed per submission, so moving a story back is a second move rather than a replay. Cancel asks first, and the row then reads Cancelling until the reaper closes it. The calendar draws a planned story as an outline in the queue's colour, and its predicted strip no longer counts planned stories as predictions. Scheduling's done step links to the Planned view. The web's `Intent` type now carries the five keys the API already served: `origin`, `scheduled_by_user_id`, `scheduled_by`, `tz` and `miss_reason`.
