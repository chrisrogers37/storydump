### Changed

- **A busy waitlist refusal is its own analytics reason, and the closing form's error is readable (#1613, #1627).** When the API turns a signup away because a shared limit is full or no slot came free, the form's "Waitlist Error" event now records `reason: busy` instead of `server_error` (only for the site route's 429 that says busy), so the busy refusals can be counted apart from real failures. The event carries nothing new. The closing form's error sentence, on the orange band, now sits on a white chip, so the alarm red reads at 7.9:1 instead of 2.5:1 on orange; the hero form, already on white, is unchanged.
