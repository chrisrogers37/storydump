### Security

- **Every SECURITY DEFINER function pins its search_path with pg_temp last (migration 103, `07` §46).** The doors pinned `pg_catalog, public`. They now pin `pg_catalog, public, pg_temp`, pg_temp named and last, as PostgreSQL's documentation asks of definer functions. One `ALTER FUNCTION ... SET search_path` per door, written out for the 29 definer functions in `public`, restates no body, so the order of merges does not matter. A census in the RLS runtime harness reads `pg_proc.proconfig` for every definer function in `public` and fails on any that lacks the path, so a door added later must name it in its own CREATE.
