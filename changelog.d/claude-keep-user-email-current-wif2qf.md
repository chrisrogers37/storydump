### Fixed

- **A user's stored email now follows their Google account when its address changes (#1579).** Sign-in used to write the verified email claim to `users.primary_email` only when the column was empty, so a person whose Google address changed kept the old one: invitations sent to their current address failed to match, removal checks missed them, and mail went to an address they might no longer use. A returning sign-in now updates `primary_email` whenever the verified claim differs from it (`identity.upsert_google_identity`). When another account already holds the new address, or takes it at the same moment, the sign-in still succeeds, the user keeps the address they had, and the clash is logged by user id (never the address); accounts are never merged (D35). Before, a returning user with no stored email whose claim another account held was refused sign-in with `identity_collision`; they now sign in the same way. A brand-new account whose email is taken is still refused. No migration.
