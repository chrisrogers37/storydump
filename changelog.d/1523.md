### Added

- **Before the browser leaves for Google, the Google Drive card now says that Google may warn it "hasn't verified this app", and how to go on (#333).** Until the Drive scope is verified, Google may put its own unverified-app page in front of the consent screen; an account added as a test user skips it. The way on is Advanced, then "Go to storydump (unsafe)" (`documentation/operations/google-oauth-verification.md`). Nothing in Storydump said so, so a person met a security warning with no word from us that it was expected. One sentence, 8px under the card's status row, now says it. It quotes the link as the page shows it, and says the access asked for is read-only, which is what `drive.readonly` means. The Connect or Reconnect button names the sentence as its description (`aria-describedby`), so a screen-reader user hears it before the browser leaves. It shows wherever the card's main action leads to Google's consent: before the first grant, and for an expired or revoked one, which must reconnect to sync again. It is not shown for a live grant. Reconnect there is an optional repair, that person has been through Google's page once, and a permanent sentence on every connected workspace would cost more than it saves. The copy is `driveConnectWarning` in `landing/src/lib/drive.ts`, pinned in `drive.test.ts`, and the card's wiring is pinned in `condition-words-contract.test.ts`.
