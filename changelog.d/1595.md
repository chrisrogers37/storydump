### Changed

- **The two public health checks cap each statement at 3 s, and a statement cancelled by its cap answers 503 (#1595).** `/health/scheduling` and `/health/posting` set a transaction-local `statement_timeout` (`health_reads.STATEMENT_TIMEOUT_MS`) before they read, which bounds each statement while the database answers. A statement cancelled during one of these reads (SQLSTATE 57014) answers 503 `statement_timeout` with `Retry-After: 1`, like a pool wait, and logs one warning for the read, not one per cached answer; every other database error stays a 500.
