### Added

- **A past post refused at preparation keeps why.** When Instagram's media for a story cannot be fetched, the refusal's evidence is recorded where the refusal lands: the asset's `validation_capture -> 'refusal'`, the story's `last_error -> 'error' -> 'refusal'` and the park's audit detail, so a slide judged gone, whose asset row is deleted, keeps it too. It holds Instagram's HTTP status, error code, subcode, type, message and trace id with the request's path; which ownership test failed, as match flags; an identity mismatch; for a slide judged gone, the children the read returned, whether the list was complete and the slide count the index recorded; a part's media type when it has no link; an untrusted host; the cap and the bytes read when a download was cut off; every CDN status across both attempts, with the host; the content type, length and status of bytes of the wrong type; and the turn's Instagram and CDN attempt counters. The access token is never copied, a signed link keeps only its host and its expiry, a request keeps only its path, and no bytes are stored. The reason codes, and what reads them, are unchanged.
