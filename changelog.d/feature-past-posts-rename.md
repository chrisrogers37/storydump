### Changed

- **The Instagram archive is called Instagram past posts everywhere.** The Settings row for a connected account's past posts reads "Instagram past posts" instead of "Your Instagram", and the Telegram notices for those stories say "This story from your Instagram past posts …". Behind them, the source's provider value is `instagram_past_posts`, its jobs are `reconcile_past_posts_accounts` and `past_posts_lifecycle_sweep`, the API fields are `past_posts_available` and `past_posts_choice`, its refusal reasons begin `past_posts_` (`invalid_past_posts_choice` among them), and each service logs `instagram past posts: on (run=…)` or `instagram past posts: off (<reason>)` at start. The rename runs only where nothing is stored under the old provider name yet, so no stored item identity, deletion tombstone or derived authorization id changes.
- **The key ring is `PAST_POSTS_HMAC_KEYS`.** It replaces `ARCHIVE_HMAC_KEYS`, which is no longer read: set the new variable on the API and the worker, with the old value, before this release deploys, then delete the old one.
- **Migration 003 renames the past-posts schema.** It renames the table (`instagram_past_posts_generations`), the four Instagram connect columns on `oauth_states`, and the constraints, indexes, triggers and functions named for the archive, and it moves stored jobs to the new kinds. It refuses to run where an Instagram past-posts source, generation or tombstone already exists, because those name the old provider.
- **New migrations run after 001 and 002.** The Schema consistency job replays the migration tail in version order, each manual file when its turn comes, and 003 refuses to run until 001 and 002 are in the ledger, so a deploy over a database that still owes them fails and changes nothing. The cutover rehearsal applies the owner steps before the files after them.

### Tests

- **The migration tests cover 003.** A base build with 001, 002 and 003 applied in order equals the current schema code; 003 refuses before 001 and 002 and where past-posts data exists; stored jobs move to the new kinds; 001's function texts stay pinned to the schema except where 003 replaced them, and 003's are pinned too. Tests and fixtures use the new names, the tombstone HMAC test vector and the reconciliation namespace were recomputed for the new provider name, and the activation log lines are pinned as `on` and `off`.
