### Fixed

- **A past-posts video whose probe fails in words that say nothing about its bytes no longer stays pending (#52).** A decoder the probe keeps closed, or its own stream bound, let the file be judged without the probe, and words that establish malformed bytes refused it; any other fault left the file pending on every try, so it never posted and never got a reason. That fault is now the probe's, not the file's: the file is judged without the probe, since its story derivation re-encodes it, and its evidence records the probe's exit status (`probe_skipped`, `fault_exit_status`).
- **A check of a past post's file that cannot finish is tried a bounded number of times (#52).** A check that could not finish left the file pending, whatever stopped it: a missing tool, a host without resource limits, the validator's time or output budget, a probe ended by a resource limit, an image over the validator's pixel budget, an image whose embedded color profile cannot be read, an image check that does not exit cleanly, or a check whose output cannot be read. The story's prepare job then tried the file again until the story's window closed, however many tries that took. Every such check now counts against the same tries as a refused fetch: it is tried again after the same doubling wait, and the last try (the eighth, by default) parks the story for review with the check's evidence. The file is not held back, so a later story tries it again.
