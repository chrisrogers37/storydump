### Fixed

- **A Telegram message whose answer was lost is no longer posted again inside the same send (#38).** `sendMessage` ran under the egress floor's default policy, which retries a call whose answer did not come back, so one text card or notice could appear up to three times while the outbox recorded only the last message. The floor's new `retry_after_send` flag is off for every call that creates a message (`sendMessage`, `sendPhoto`, `sendVideo`, `sendDocument`): such a call is attempted again only when its request never left (no connection was made, or none came free in the pool), and an answer lost after the request was sent goes to the outbox's ambiguity policy for its kind. An upload that could not connect is now retried inside its budget instead of waiting out the ambiguity backoff. Edits keep the floor's retries, since an edit of the same message is idempotent.
