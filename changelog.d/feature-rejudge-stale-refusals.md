### Changed

- **A stored refusal of a past post's file counts only while the rules that refused it are the current ones.** Both overloads of `fn_source_asset_suitability` take the validator's matrix version as their last parameter (`p_matrix_version`, defaulting to NULL) and honour a stored `unsupported` verdict only when the slide's validation capture is stamped with it; an older or unstamped verdict leaves the slide a candidate again, `validation_pending` in strict mode, so the next story prepared from it fetches and judges the file again. A call that passes no version (NULL) keeps every stored refusal, as before. The catalog's own `unsupported_media` exclusion is unchanged. Migration `007_suitability_matrix_version.sql` replaces both overloads of the function with the new signatures.
